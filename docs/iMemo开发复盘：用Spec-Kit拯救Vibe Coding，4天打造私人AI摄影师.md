## 什么是 Spec-Kit？它如何拯救 Vibe Coding？

刚开始使用 AI 工具编程的朋友们，可能都遇到过这种情况：跟 AI（比如 Cursor、Claude Code）说"帮我写个 XX 功能"，它就开始噼里啪啦写代码。但写出来的东西经常：

- 理解错了你的需求
- 技术选型很奇怪
- 代码能跑但不好维护
- 需要反复修改和沟通

这就是 **"Vibe Coding"（感觉式编程）** 的典型症状。

### Spec-Kit 的核心理念

**它把开发过程像流水线一样，拆分成了 5 个明确的步骤：**

**第 1 步：定规矩 (`/speckit.constitution`)**

> "这个项目要注重隐私保护、代码质量、性能..."
> → 这相当于给 AI 立下项目"宪法"，后续所有工作都得遵守。

**第 2 步：说需求 (`/speckit.specify`)**

> "我要做个 AI 摄影师应用，能生成各种风格的艺术照..."
> → 在这一步，你只说想要什么功能，完全不提技术实现。

**第 3 步：定技术方案 (`/speckit.plan`)**

> "用 Tauri + Next.js，数据库用 SQLite..."
> → AI 会基于你的需求和"宪法"，提出最合适的技术栈让你确认。

**第 4 步：列任务清单 (`/speckit.tasks`)**

> 自动把方案拆解成一个个具体、可执行的小任务。
> → 就像把一个大项目拆分成每日的 TODO List。

**第 5 步：开始干活 (`/speckit.implement`)**

> AI 按照任务清单，有条不紊地逐一实现功能。
> → 告别混乱，进入有序开发。

![](https://files.mdnice.com/user/66105/9e6ea340-9e67-47d1-831f-f36a5c28a95d.jpg)

### 核心优势是什么？

> **强制 AI 先搞清楚"要做什么"，再考虑"怎么做"。**

这就像你找装修公司：

- **❌ 错误方式:** 直接说"给我装修"，结果装成了你不喜欢的风格。
- **✅ 正确方式:** 先明确"我要北欧风格、3 个卧室"，再讨论用什么材料、哪个工人。

![](https://files.mdnice.com/user/66105/dedf24f4-df6c-4260-9ab3-9fe353aa5585.jpg)

### 为什么它对 Claude Code 特别有效？

1. **防止 AI "想当然"** - 不会一上来就自作主张选技术栈
2. **减少返工** - 需求和方案都确认清楚了再动手
3. **质量有保障** - 每一步都有清晰的文档和检查清单
4. **适合团队** - 产出的规格、方案、任务等文档，团队其他人也能看懂

简单说：`spec-kit` 给 AI 装上了一个**"产品经理 + 架构师"的大脑**，让它不再是个只会敲代码的"码农"。

## 实战：用 Spec-Kit + Claude Code 开发 iMemo

接下来，我将演示如何一步步使用 `spec-kit` 开发我的"私人 AI 摄影师"应用 **iMemo**。

### 产品定位

在开始开发前，我先明确了产品的核心定位：

> **iMemo - 您的私人 AI 摄影师**
>
> 就像有钱人家有私人医生、私人律师一样，
> 我们要让每个普通家庭都能拥有自己的私人 AI 摄影师。

**核心功能**：
- 📸 基于 SeeDream 4.0 的强大图生图能力
- 🎨 支持婚纱照、百日照、周岁照等 20+ 种艺术风格
- 🔒 所有数据 100% 本地存储，绝不上传云端
- 💰 节省照相馆费用，随时随地创作奇幻照片

### Spec-Kit 的安装和使用

关于 Spec-Kit 的详细安装步骤和使用方法，我之前写过一篇完整的教程，这里不再重复。如果你是第一次接触 Spec-Kit，建议先阅读：

> 📖 **完整教程**：[《如何用 Spec-Kit 拯救 Vibe Coding》](https://mp.weixin.qq.com/s/ScEIJxDkRJ8iqozOLyVIkw)

简单来说，只需要三步：
1. **初始化项目**：`uvx --from git+https://github.com/github/spec-kit.git specify init --here`
2. **启动 Claude Code**：在终端输入 `claude`
3. **遵循 5 步流程**：constitution → specify → plan → tasks → implement

下面我重点分享 iMemo 项目的开发过程和关键决策：

### 开发过程与关键决策

#### 1️⃣ 建立项目原则（可选但强烈推荐）

我使用 `/speckit.constitution` 命令，为 iMemo 应用创建了开发原则，这能确保 AI 在后续每一步都牢记这些核心要求：

> 1. **隐私保护优先** - 所有照片和数据必须只存储在本地，绝不上传到服务器
> 2. **AI 原生体验** - 充分利用 SeeDream 4.0 的人物一致性能力，提供专业摄影师级别的作品
> 3. **用户体验优于技术复杂度** - 面向非技术用户（普通家长），提供预设风格模板和一键生成
> 4. **优雅降级与错误恢复** - 生成失败时给出清晰的错误提示和重试机制
> 5. **增量价值交付** - 功能按优先级独立开发，MVP 先做核心的照片生成功能

#### 2️⃣ 描述功能需求

接着，使用 `/speckit.specify` 告诉 AI 你想要什么。**记住，只谈功能，不谈技术！**

> 我要做一个"私人 AI 摄影师"桌面应用 iMemo。
>
> **核心功能**：
> - 用户可以上传个人照片到本地照片库
> - 选择人生阶段（结婚、百日照、周岁照等）
> - 选择艺术风格（每个阶段有多种精选风格）
> - 点击生成后，应用调用 SeeDream 4.0 API，生成一套风格统一、保持人物面部特征的艺术照
> - 生成结果可以收藏、下载、保存到系统相册
> - 所有数据和图片都保存在本地 SQLite 数据库
>
> **隐私要求**：
> - 绝不上传用户照片到云端
> - AI 处理通过用户配置的 API 完成
> - 可以自建 API 服务

![](https://files.mdnice.com/user/66105/414c5d5d-9bf5-4d17-9e04-d246b6960e82.png)

#### 3️⃣ 定义技术方案

需求明确后，执行 `/speckit.plan`。Claude Code 会基于之前的需求和原则，提出一套完整的技术方案。

**它为我生成的技术栈**：
- **前端框架**: Next.js 14（App Router）
- **桌面框架**: Tauri 2.x（比 Electron 更轻量）
- **UI 组件**: Radix UI + Tailwind CSS
- **状态管理**: Zustand
- **数据库**: SQLite（本地存储）
- **AI 模型**: SeeDream 4.0（BytePlus）
- **语言**: TypeScript + Rust

这个方案非常符合一个注重隐私、本地优先的桌面应用需求！

![](https://files.mdnice.com/user/66105/bcbc29c9-4abf-4887-a3b0-c4166891939f.png)

#### 4️⃣ 生成任务清单

方案确认后，使用 `/speckit.tasks` 命令。Claude 会自动分析 `plan` 文件，生成一份详细、可执行的任务列表。

**任务清单示例**：
1. 初始化 Tauri + Next.js 项目结构
2. 配置 SQLite 数据库和表结构
3. 实现照片库管理功能
4. 实现人生阶段和风格选择 UI
5. 集成 SeeDream 4.0 API
6. 实现 AI 照片生成核心流程
7. 添加生成进度显示
8. 实现收藏和导出功能
9. 添加重试机制
10. 完善错误处理和用户提示

![](https://files.mdnice.com/user/66105/6a55b8cc-13fa-472a-b011-74f94ea6a4ff.png)

#### 5️⃣ 开始实现！

万事俱备，现在只需执行 `/speckit.implement`。Claude 就会像一个经验丰富的工程师，按照任务清单逐一完成代码实现。

**这个过程中**：
- ✅ Claude 会自动创建所有必要的文件和目录
- ✅ 生成完整的 TypeScript 和 Rust 代码
- ✅ 配置 Tailwind CSS 样式系统
- ✅ 实现所有数据库操作
- ✅ 集成 API 调用和错误处理
- ✅ **我没有手写一行代码！**

## 💡 实用技巧与最佳实践

### 使用 Spec-Kit 的关键技巧

1. **每一步都可以反复修改**：
   - 觉得 `spec` 不对？直接让 Claude 修改
   - 技术栈想换？重新运行 `/speckit.plan` 即可
   - 不要怕修改，修改的成本很低

2. **使用 `/speckit.clarify` 澄清需求**：
   - 在 `plan` 之前运行
   - Claude 会主动向你提问
   - 把需求细节弄得更清楚，避免后面返工

3. **检查 Checklist**：
   - 每个 `spec.md` 文件里都有 Review Checklist
   - 用来检查 AI 的交付物是否满足预期
   - 确保质量达标

4. **随时中断并调整**：
   - Claude 不会一次性跑完所有任务
   - 你可以在过程中随时介入
   - 修正它的方向，保持掌控力

### 🎯 核心要点

- **不要一上来就让 Claude 写代码**，先走 `spec-kit` 流程
- **Specify 阶段不谈技术**，只谈业务需求
- **Plan 阶段再定技术栈**，让决策有理有据
- **Implement 前确保 Spec 和 Plan 都已确认无误**
- **充分信任 AI，但保持审核和反馈**

这样用下来，Claude 生成的代码质量会比直接 vibe coding 高很多，而且文档齐全、思路清晰！
