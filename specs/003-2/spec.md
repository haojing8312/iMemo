# Feature Specification: 多人照片生成模式选择

**Feature Branch**: `003-2`
**Created**: 2025-10-15
**Status**: Draft
**Input**: User description: "我们现在生成照片有2种模式，一种是上传照片，生成，另一种是在照片库选择照片，所以为了支持多人照片生成，我建议开始生成照片之前，要先确定是生成多人风格还是单人风格，然后再上传或者选择单张/多张照片，注意多人要求必须上传多张单人照如爸爸、妈妈、孩子的照片；然后再根据单人还是多人选择对应风格类型。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 单人照片生成流程 (Priority: P1)

用户张妈妈想为她的百日宝宝生成各种艺术风格的纪念照片。她打开应用后,需要先选择"单人模式",然后上传或从照片库选择一张宝宝的清晰照片,系统展示适合单人的所有风格供她选择,最后生成多张不同风格的宝宝照片。

**Why this priority**: 这是最基础和最常用的使用场景,90%以上的用户都是为单个孩子生成照片。没有这个功能,产品无法交付核心价值。

**Independent Test**: 可以通过完整走一遍单人生成流程来独立测试:用户选择单人模式 → 上传1张照片 → 选择风格 → 成功生成照片。即使多人功能未实现,单人功能也能完整交付价值。

**Acceptance Scenarios**:

1. **Given** 用户在主界面, **When** 点击"开始生成"按钮, **Then** 系统展示模式选择界面,包含"单人照片"和"多人照片"两个选项
2. **Given** 用户选择"单人照片"模式, **When** 点击"继续", **Then** 系统跳转到照片选择界面,允许上传或从照片库选择单张照片
3. **Given** 用户已上传1张宝宝照片, **When** 进入风格选择页面, **Then** 系统只展示标记为"单人风格"的所有可用风格(如居家温馨风、森系清新风等)
4. **Given** 用户选择了单人风格并确认, **When** 点击"开始生成", **Then** 系统使用这1张照片作为参考,成功生成多张风格化照片

---

### User Story 2 - 多人照片生成流程(上传模式) (Priority: P2)

用户李妈妈想生成一张温馨的全家福,包括她自己、丈夫和宝宝。她选择"多人模式",然后依次上传3张单人照片:宝宝的照片、妈妈的照片、爸爸的照片。系统验证每张照片都是单人清晰照片后,展示适合多人场景的风格(如"温馨亲子互动风"),最后生成一张包含3个人的合成照片,每个人的面部特征都与参考照保持一致。

**Why this priority**: 这是多人生成的核心场景,满足用户生成家庭合照的需求。虽然不如单人常用,但对于家庭纪念照具有重要价值。

**Independent Test**: 可以通过完整走一遍多人生成流程来独立测试:用户选择多人模式 → 上传3张单人照(宝宝+爸爸+妈妈) → 选择多人风格 → 成功生成全家福照片。即使单人功能已有,多人功能也是独立可测的增量价值。

**Acceptance Scenarios**:

1. **Given** 用户在模式选择界面, **When** 选择"多人照片"模式, **Then** 系统展示说明文字:"请上传2-4张单人照片,每张照片只包含一个人(如:宝宝照片、妈妈照片、爸爸照片)"
2. **Given** 用户选择多人模式后进入上传界面, **When** 用户依次上传3张照片, **Then** 系统验证每张照片是否为单人照(人脸检测数量=1),如果不符合则提示错误
3. **Given** 用户成功上传3张符合要求的单人照, **When** 进入风格选择页面, **Then** 系统只展示标记为"多人风格"的风格(如"温馨亲子互动风"),隐藏所有单人风格
4. **Given** 用户选择多人风格"温馨亲子互动风", **When** 点击"开始生成", **Then** 系统将3张单人照作为参考数组传给AI生成接口,成功生成包含3人的合成照片
5. **Given** 用户上传了超过4张照片, **When** 尝试继续, **Then** 系统提示"最多支持4人",并禁止继续操作

### User Story 3 - 多人照片生成流程(照片库选择模式) (Priority: P2)

用户王妈妈之前已经上传过宝宝、自己和丈夫的照片到应用的照片库中。这次她想生成全家福时,选择"多人模式",然后从照片库中勾选已有的3张单人照片,而不是重新上传。系统验证选择的照片符合要求后,继续后续的风格选择和生成流程。

**Why this priority**: 这是多人生成的另一个入口,提升用户体验,避免重复上传已有照片。与 Story 2 同等优先级,都是 P2。

**Independent Test**: 可以通过完整走一遍照片库选择流程来独立测试:用户选择多人模式 → 从照片库勾选3张已有单人照 → 选择多人风格 → 成功生成全家福照片。这是独立于上传流程的另一条路径。

**Acceptance Scenarios**:

1. **Given** 用户选择多人模式后在照片选择界面, **When** 点击"从照片库选择", **Then** 系统展示照片库中所有已上传的照片,支持多选(最少2张,最多4张)
2. **Given** 用户从照片库勾选了3张照片, **When** 点击"确认选择", **Then** 系统验证每张照片是否为单人照,如果不符合则提示"请选择单人照片"
3. **Given** 用户选择的照片中有一张包含2人, **When** 尝试确认, **Then** 系统高亮显示问题照片并提示"该照片包含多人,请选择单人照片"
4. **Given** 用户成功从照片库选择3张符合要求的单人照, **When** 进入风格选择页面, **Then** 后续流程与 Story 2 相同,展示多人风格并正常生成

### User Story 4 - 参考照片库与生成照片相册分离管理 (Priority: P2)

用户陈妈妈使用应用一段时间后,发现照片库里既有她上传的原始参考照片(宝宝、爸爸、妈妈的单人照),也有AI生成的各种风格照片,导致选择参考照片时很难找到想要的照片。她希望系统能将参考照片库和生成照片相册分开:参考照片库只显示她手工上传的原始照片,方便选择;生成照片相册则自动保存所有AI生成的照片,并支持按照片类型(上传/AI生成)、入册日期、里程碑、风格等条件筛选,便于查找和管理纪念照。

**Why this priority**: 这是照片管理的核心优化,解决用户实际使用中的痛点问题。随着生成照片数量增加,混合存储会严重影响用户体验和照片选择效率。与多人生成功能同等重要,都是 P2。

**Independent Test**: 可以通过完整的照片管理流程来独立测试:用户上传3张原始照片 → 生成10张AI照片 → 在参考照片库中只看到3张上传的照片 → 在生成照片相册中看到10张AI照片 → 使用筛选条件(如"百日照+森系清新风")快速找到特定照片。这是独立的照片存储和查询逻辑。

**Acceptance Scenarios**:

1. **Given** 用户手工上传了3张原始单人照, **When** 这些照片保存后, **Then** 它们只出现在"参考照片库"中,不出现在"生成照片相册"中
2. **Given** 用户完成一次照片生成(4张照片), **When** 生成成功后, **Then** 这4张AI生成的照片自动保存到"生成照片相册"中,不出现在"参考照片库"中
3. **Given** 用户在生成流程中选择参考照片, **When** 点击"从照片库选择", **Then** 系统只展示"参考照片库"中的照片(用户上传的原始照片),不显示AI生成的照片
4. **Given** 用户打开"生成照片相册", **When** 查看相册, **Then** 系统显示所有AI生成的照片,并提供筛选选项:照片类型(用户上传/AI生成)、入册日期、里程碑、风格
5. **Given** 用户在相册中选择筛选条件"百日照+森系清新风", **When** 应用筛选, **Then** 系统只显示符合这两个条件的生成照片
6. **Given** 用户在相册中选择照片类型筛选"用户上传", **When** 应用筛选, **Then** 系统显示用户手工上传的原始照片(相当于"参考照片库"的另一个入口)
7. **Given** 用户在相册中选择入册日期筛选"最近7天", **When** 应用筛选, **Then** 系统只显示最近7天内添加到相册的照片

### User Story 5 - 模式切换与照片重新选择 (Priority: P3)

用户赵妈妈最初选择了"单人模式"并上传了1张宝宝照片,但进入风格选择页面后,她突然想生成全家福。她需要能够返回上一步,切换到"多人模式",重新选择照片(需要补充爸爸妈妈的照片),然后看到多人风格选项。

**Why this priority**: 这是提升用户体验的优化功能,允许用户在流程中途改变主意。不是核心功能,但能减少用户操作失误和重新开始的挫败感。

**Independent Test**: 可以通过测试模式切换流程来独立验证:用户选择单人模式并上传照片 → 返回并切换到多人模式 → 系统清空之前的照片选择 → 用户重新上传多张照片 → 正常进入多人风格选择。这是独立的流程控制逻辑。

**Acceptance Scenarios**:

1. **Given** 用户已选择单人模式并上传1张照片, **When** 点击"返回"按钮, **Then** 系统返回到模式选择界面,允许重新选择模式
2. **Given** 用户从单人模式返回后切换到多人模式, **When** 进入照片选择界面, **Then** 系统清空之前选择的单张照片,提示"请上传2-4张单人照片"
3. **Given** 用户已选择多人模式并上传3张照片, **When** 点击"返回"后切换到单人模式, **Then** 系统清空之前选择的多张照片,提示"请上传1张照片"
4. **Given** 用户在风格选择页面, **When** 点击"返回"按钮, **Then** 系统返回到照片选择界面,保持当前模式和已选照片不变,允许用户修改照片

---

### Edge Cases

- **照片数量限制**: 单人模式必须只有1张照片,多人模式必须有2-4张照片。如果用户在单人模式上传多张,系统应提示错误或自动只保留第1张。
- **人脸检测失败**: 如果上传的照片无法检测到人脸,系统应提示"未检测到人脸,请上传清晰的人像照片"。
- **多人照片误上传**: 如果用户在多人模式上传了一张包含多人的照片(如已有的全家福),系统应提示"检测到多人,请上传单人照片"。
- **照片质量过低**: 如果照片模糊、光线太暗或角度不正,系统应在生成前验证并提示"照片质量不符合要求,请重新选择"。
- **风格兼容性**: 如果用户选择的里程碑(如"出生纪念")不支持多人风格,系统应在模式选择时禁用"多人照片"选项,并显示提示"该里程碑暂不支持多人照片"。
- **网络中断**: 如果在上传照片或生成过程中网络中断,系统应保存用户当前的选择状态,允许恢复而不是重新开始。
- **混合模式禁止**: 用户不能在同一次生成任务中混合单人和多人风格。如果用户选择了单人模式,风格列表应完全隐藏多人风格;反之亦然。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在照片生成流程的第一步提供模式选择界面,包含"单人照片"和"多人照片"两个互斥选项
- **FR-002**: 系统必须在模式选择界面清晰说明每个模式的要求:单人模式需要1张照片,多人模式需要2-4张单人照片
- **FR-003**: 系统必须根据用户选择的模式,在照片选择界面强制执行照片数量限制:单人模式=1张,多人模式=2-4张
- **FR-004**: 系统必须对多人模式上传的每张照片进行人脸检测,确保每张照片只包含1人,否则拒绝该照片并提示错误
- **FR-005**: 系统必须在风格选择页面根据当前模式过滤风格列表:单人模式只显示单人风格,多人模式只显示多人风格
- **FR-006**: 系统必须支持两种照片选择方式:直接上传新照片,或从照片库选择已有照片,两种方式都需遵守模式的照片数量限制
- **FR-007**: 系统必须在用户切换模式时清空之前选择的照片,提示用户重新选择符合新模式要求的照片
- **FR-008**: 系统必须在调用AI生成接口时,根据模式传递不同的参数:单人模式传递1张照片的base64,多人模式传递多张照片的base64数组
- **FR-009**: 系统必须在多人模式下限制最多4人,如果用户尝试上传第5张照片,应阻止操作并提示"最多支持4人"
- **FR-010**: 系统必须在照片选择完成后,在下一步界面显示已选照片的缩略图预览和数量(如"已选择3张照片")
- **FR-011**: 系统必须持久化用户的模式选择和照片选择状态,如果应用意外关闭后重新打开,能够恢复到之前的选择状态
- **FR-012**: 系统必须为多人模式的风格配置添加元数据标识(如 `requiresMultiplePhotos: true`, `minPhotos: 2`, `maxPhotos: 4`),用于风格过滤逻辑
- **FR-013**: 系统必须将照片存储分为两个独立集合:"参考照片库"(用户上传的原始照片)和"生成照片相册"(AI生成的照片),两者不能混合
- **FR-014**: 系统必须在用户手工上传照片时,自动将这些照片保存到"参考照片库"中,同时为每张照片添加元数据标识 `source: 'user_uploaded'`
- **FR-015**: 系统必须在AI生成照片完成后,自动将生成的照片保存到"生成照片相册"中,同时为每张照片添加元数据(来源标识 `source: 'ai_generated'`、生成日期、里程碑ID、风格ID)
- **FR-016**: 系统必须在生成流程的照片选择步骤中,当用户点击"从照片库选择"时,只展示"参考照片库"中的照片,隐藏所有AI生成的照片
- **FR-017**: 系统必须在"生成照片相册"界面提供筛选功能,支持以下筛选条件:照片类型(用户上传/AI生成)、入册日期范围、里程碑、风格
- **FR-018**: 系统必须支持照片类型筛选:当用户选择"用户上传"时,相册显示原始参考照片;当选择"AI生成"时,相册只显示AI生成的照片
- **FR-019**: 系统必须支持日期范围筛选,允许用户选择预设范围(如"最近7天"、"最近30天"、"全部")或自定义日期范围
- **FR-020**: 系统必须支持组合筛选,允许用户同时应用多个筛选条件(如"百日照 + 森系清新风 + 最近7天"),筛选结果必须满足所有选中的条件
- **FR-021**: 系统必须在相册列表中为每张照片显示关键元数据(缩略图、生成日期、里程碑标签、风格标签),便于用户快速识别

### Key Entities

- **GenerationMode(生成模式)**: 表示用户选择的生成类型,枚举值为 `SINGLE_PERSON`(单人) 或 `MULTI_PERSON`(多人)。包含属性:模式名称、说明文字、照片数量要求(最少/最多)、兼容的风格ID列表。

- **PhotoSelection(照片选择)**: 表示用户选择的照片集合。包含属性:选择来源(上传/照片库)、照片列表(文件路径或照片库ID数组)、照片数量、每张照片的验证状态(是否通过人脸检测)。与 `GenerationMode` 关联,必须符合当前模式的数量要求。

- **StyleMetadata(风格元数据)**: 表示每个风格的配置信息。包含属性:风格ID、风格名称、是否为多人风格(`isMultiPerson: boolean`)、所需最少/最多照片数量、兼容的里程碑列表。用于风格过滤逻辑。

- **GenerationTask(生成任务)**: 表示一次完整的照片生成任务。包含属性:任务ID、生成模式(`GenerationMode`)、选择的照片列表(`PhotoSelection`)、选择的风格ID、里程碑ID、任务状态(进行中/已完成/失败)、生成结果(图片URL数组)。

- **ReferencePhotoLibrary(参考照片库)**: 表示用户上传的原始照片集合,用于作为AI生成的参考。包含属性:照片ID列表、每张照片的元数据(`source: 'user_uploaded'`、上传日期、文件路径、缩略图路径、人脸检测结果)。此库中的照片仅用于选择参考,不包含AI生成的照片。

- **GeneratedPhotoAlbum(生成照片相册)**: 表示所有AI生成的照片集合,用于浏览和管理生成结果。包含属性:照片ID列表、每张照片的元数据(`source: 'ai_generated'`、生成日期、里程碑ID、风格ID、任务ID、文件路径、缩略图路径)。此相册专门存储AI生成的照片,支持多维度筛选。

- **PhotoFilter(照片筛选器)**: 表示相册的筛选条件配置。包含属性:照片类型筛选(用户上传/AI生成/全部)、日期范围筛选(起始日期、结束日期或预设范围)、里程碑ID筛选(单选或多选)、风格ID筛选(单选或多选)、当前激活的筛选条件列表。用于生成照片相册的查询逻辑。

- **PhotoMetadata(照片元数据)**: 表示单张照片的完整元数据信息。包含属性:照片ID、来源标识(`source: 'user_uploaded' | 'ai_generated'`)、创建日期、文件路径、缩略图路径、关联的里程碑ID(仅AI照片)、关联的风格ID(仅AI照片)、关联的任务ID(仅AI照片)、人脸检测结果(仅用户上传照片)。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够在3步内完成模式选择、照片选择和风格选择,从开始到确认生成的总时间不超过2分钟
- **SC-002**: 单人模式的照片验证成功率达到95%以上(排除用户上传非人像照片的情况)
- **SC-003**: 多人模式的人脸检测准确率达到90%以上,能正确识别单人照片并拒绝多人照片
- **SC-004**: 用户在选择模式后能够成功切换模式并重新选择照片,切换操作的成功率达到100%(无报错)
- **SC-005**: 风格过滤逻辑准确率达到100%:单人模式下不会显示多人风格,多人模式下不会显示单人风格
- **SC-006**: 多人照片生成的成功率达到85%以上,生成的照片中每个人的面部特征与参考照保持明显一致性
- **SC-007**: 用户完成首次多人照片生成的平均时间不超过5分钟(从模式选择到看到生成结果)
- **SC-008**: 在网络波动或应用重启后,95%以上的用户能够成功恢复之前的选择状态,无需重新操作
- **SC-009**: 照片分离准确率达到100%:用户上传的照片只出现在参考照片库,AI生成的照片只出现在生成照片相册,无混合或错误归类
- **SC-010**: 相册筛选功能的响应时间不超过1秒,即使相册包含1000+张照片,筛选结果也能快速返回
- **SC-011**: 用户在选择参考照片时,能够100%准确地只看到原始上传照片,不会看到AI生成照片干扰选择
- **SC-012**: 用户使用组合筛选条件(如"百日照+森系清新风+最近7天")时,筛选准确率达到100%,返回的照片必须同时满足所有条件
- **SC-013**: 用户在首次使用照片分离功能后,照片查找效率提升60%以上(通过任务完成时间对比验证),用户满意度达到90%以上
