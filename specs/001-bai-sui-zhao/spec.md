# Feature Specification: 百岁照生成功能

**Feature Branch**: `001-bai-sui-zhao`
**Created**: 2025-10-08
**Status**: Draft
**Input**: User description: "百岁照生成功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 快速生成单风格百岁照 (Priority: P1)

家长小王的宝宝刚满100天,她想要一组温馨的百岁照留作纪念,但不想去影楼拍摄(担心隐私+费用高)。她打开HomeMemo应用,上传了2张宝宝近期照片,选择"居家暖光温馨风"风格,点击生成按钮。30秒内,系统自动生成4张不同表情和姿势的百岁照,小王挑选了最满意的2张保存到相册。

**Why this priority**: 这是产品的核心价值 - 让家长能快速、私密地获得高质量百岁照。没有这个功能,产品就没有存在意义。这个故事完整覆盖了"上传→选风格→生成→保存"的最小可用路径。

**Independent Test**: 用户可以完整地从零开始生成并保存百岁照,无需依赖其他功能。测试方式:准备1-2张婴儿照片,选择任一风格,验证能成功生成4张图片并保存。

**Acceptance Scenarios**:

1. **Given** 用户已安装应用且首次使用, **When** 点击"生成百岁照"入口, **Then** 看到照片上传界面,显示"请上传1-5张宝宝近期照片"的提示
2. **Given** 用户已上传1张照片, **When** 选择"居家暖光温馨风"并点击"开始生成", **Then** 显示进度条,30秒内生成完成,展示4张风格一致但表情/姿势不同的照片缩略图
3. **Given** 生成已完成, **When** 用户点击任一缩略图, **Then** 打开高清预览,可左右滑动查看其他生成结果
4. **Given** 用户在预览界面, **When** 勾选2张照片并点击"保存", **Then** 照片自动保存到本地相册,文件名格式为"20251008-暖光温馨-1.jpg"

### User Story 2 - 多风格批量生成 (Priority: P2)

家长李女士想要更多风格选择,她一次性选择了"暖光温馨风"+"森系清新风"+"梦幻柔光风"3种风格,系统同时生成3组(共12张)照片,她可以从中挑选最喜欢的风格组合。

**Why this priority**: 提升用户体验和照片多样性,但不是MVP必需功能(单风格已经可用)。增加这个功能能让产品更有竞争力,满足"想要多种风格对比"的用户需求。

**Independent Test**: 在P1功能基础上,验证多选风格后能生成多组照片。测试方式:上传照片后选择2-3种风格,验证每种风格都生成4张照片,且风格特征明显区分。

**Acceptance Scenarios**:

1. **Given** 用户已上传照片, **When** 同时勾选3种风格并点击生成, **Then** 进度条显示"正在生成第1/3组",依次完成所有风格的生成
2. **Given** 多风格生成完成, **When** 用户查看结果, **Then** 照片按风格分组展示,每组显示风格名称标签(如"暖光温馨风 4张")
3. **Given** 用户查看多风格结果, **When** 选择不同组的照片保存, **Then** 文件名自动包含对应风格名称,便于后续区分

### User Story 3 - 照片编辑与重试 (Priority: P2)

家长张先生上传的照片背景比较杂乱,他希望先裁剪掉多余部分再生成。生成后发现其中1张照片表情不够自然,他想针对这张重新生成一次,而不是全部重来。

**Why this priority**: 提升生成成功率和用户满意度,减少返工。裁剪功能帮助用户优化输入质量,单张重试避免浪费时间重新生成整组。

**Independent Test**: 验证上传后能裁剪,生成后能针对单张重试。测试方式:上传照片→裁剪为3:4比例→生成→对某张结果点击"重新生成"→验证仅该张更新。

**Acceptance Scenarios**:

1. **Given** 用户已上传1张照片, **When** 点击照片进入编辑模式, **Then** 显示裁剪框,支持选择"正方形/3:4竖版/4:3横版",拖动调整裁剪区域
2. **Given** 用户完成裁剪, **When** 点击"确认", **Then** 预览界面显示裁剪后的照片,生成时使用裁剪后的版本
3. **Given** 生成完成后用户查看4张结果, **When** 对第2张点击"重新生成", **Then** 仅第2张重新生成(保持同风格),其他3张不变,新结果替换原第2张的位置
4. **Given** 重新生成失败(如网络问题), **When** 显示错误提示, **Then** 提示"生成失败,请检查网络连接后重试",原第2张照片保持不变,可再次点击重试

### User Story 4 - 历史记录管理 (Priority: P3)

家长周女士一个月前生成过一批百岁照,现在想找回之前生成的"复古胶片风"照片,她在历史记录中找到该次生成任务,重新查看并下载了之前未保存的几张。

**Why this priority**: 便利性功能,避免用户忘记保存后无法找回。但不影响核心生成流程,属于体验优化。

**Independent Test**: 验证生成记录被自动保存,可查看历史并重新下载。测试方式:生成一批照片→退出应用→重新打开→在历史记录中找到之前的生成结果。

**Acceptance Scenarios**:

1. **Given** 用户历史上生成过3次百岁照, **When** 点击"历史记录"入口, **Then** 按时间倒序显示3条记录,每条显示"生成时间+风格+缩略图"
2. **Given** 用户点击某条历史记录, **When** 进入详情, **Then** 显示该次生成的所有照片,支持预览和重新保存
3. **Given** 用户在历史记录详情, **When** 长按某条记录选择"删除", **Then** 弹出确认提示"删除后无法恢复,是否继续?",确认后从历史中移除

---

### Edge Cases

- **照片质量不足**: 用户上传的照片模糊、光线极暗或婴儿面部被遮挡超过50% → 系统在点击"开始生成"前进行质量检测,提示"照片质量不足,建议重新拍摄:光线充足、正面清晰"
- **网络中断**: 生成过程中网络断开 → 显示"网络连接中断,已保存进度",恢复网络后可继续/重试当前生成任务
- **同时生成过多风格**: 用户选择超过3种风格 → 系统限制最多同时生成3种,超过时提示"单次最多选择3种风格,请取消部分选择"
- **存储空间不足**: 保存照片时设备存储空间不足 → 提示"存储空间不足,请清理后重试",已生成的照片保留在临时缓存,清理空间后可重新保存
- **AI生成失败**: nano banana API返回错误(如内容审核未通过) → 提示"生成失败,请检查照片内容是否符合规范",提供重试按钮
- **上传照片格式不支持**: 用户上传HEIC/WebP等格式 → 自动转换为JPG,若转换失败则提示"不支持的格式,请上传JPG或PNG"
- **相似度设置极端值**: 用户将相似度设为"极高"导致生成结果与原图几乎无差异 → 生成前提示"相似度过高可能导致风格效果不明显,建议选择'中'或'低'"

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持上传1-5张婴儿照片,格式限定为JPG和PNG,单张大小限制10MB以内
- **FR-002**: 系统必须提供至少6种预设风格模板(暖光温馨、森系清新、卡通动漫、复古胶片、梦幻柔光、节日主题),每种风格包含固定的Prompt模板
- **FR-003**: 系统必须支持照片裁剪功能,提供正方形(1:1)、竖版(3:4)、横版(4:3)三种比例选项
- **FR-004**: 系统必须在生成前对照片质量进行验证,检测项包括:分辨率≥512x512、清晰度评分≥60分、面部检测成功
- **FR-005**: 系统必须调用云端AI服务(如nano banana API)进行图片生成,每种风格生成4张不同表情/姿势的照片
- **FR-006**: 系统必须显示生成进度(百分比形式)和预计剩余时间
- **FR-007**: 系统必须支持相似度调节,提供"高/中/低"三档选项,默认为"中"
- **FR-008**: 系统必须支持同时选择1-3种风格进行批量生成
- **FR-009**: 系统必须提供生成结果的缩略图预览(200x200px)和高清查看(原始分辨率)
- **FR-010**: 系统必须支持对单张生成结果进行重新生成,保持相同风格参数
- **FR-011**: 系统必须支持多选照片并批量保存到本地相册,文件命名格式为"日期-风格名-序号.jpg"
- **FR-012**: 系统必须自动保存生成历史,记录生成时间、选择的风格、上传的原图(缩略图)和生成结果
- **FR-013**: 用户必须能够查看、删除历史记录,删除时同步清理本地缓存的图片文件
- **FR-014**: 系统必须在首次调用AI服务前显示隐私声明,告知"照片仅在生成时传输,不会存储在云端",需要用户确认同意
- **FR-015**: 系统必须处理生成失败的情况,提供明确的错误提示(网络错误、内容审核失败、照片质量不足等)和重试入口
- **FR-016**: 系统必须支持用户手动清理历史记录和缓存,提供"一键清理所有历史"功能

### Key Entities

- **Photo Upload Record (照片上传记录)**: 用户上传的原始照片信息,包含:上传时间、文件路径、尺寸、是否已裁剪、裁剪参数(比例+坐标)
- **Style Template (风格模板)**: 预设的生成风格,包含:风格ID、风格名称(中文)、Prompt模板文本、缩略图示例、推荐场景描述
- **Generation Task (生成任务)**: 单次生成请求,包含:任务ID、创建时间、使用的照片列表、选择的风格列表、相似度设置、任务状态(进行中/成功/失败)
- **Generated Image (生成结果)**: AI生成的照片,包含:所属任务ID、风格ID、生成序号(1-4)、文件路径、生成时间、是否已保存到相册
- **Generation History (生成历史)**: 历史记录条目,关联一个Generation Task,用于用户查看和管理过往生成记录

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从打开应用到保存第一张百岁照的完整流程耗时≤2分钟(包括上传1张照片+选择1种风格+生成+保存)
- **SC-002**: 单张照片生成耗时≤30秒(基于正常网络环境,使用nano banana标准套餐)
- **SC-003**: 照片质量验证准确率≥90%(模糊/光线不足的照片能被正确识别并提示)
- **SC-004**: 生成成功率≥95%(在照片通过质量验证的前提下,排除用户主动取消和网络中断)
- **SC-005**: 用户首次使用时,90%的用户能在无任何指导的情况下成功完成第一次生成(可用性测试指标)
- **SC-006**: 多风格同时生成时(3种风格),总耗时≤90秒(允许并发或串行优化)
- **SC-007**: 历史记录加载速度≤1秒(包含最近20条记录的缩略图)
- **SC-008**: 用户对生成照片质量的满意度≥4分(5分制),通过应用内反馈收集
- **SC-009**: 单张重新生成的成功率≥95%,且耗时与首次生成相当(≤30秒)
- **SC-010**: 应用本地存储占用≤500MB(包括历史记录、缓存图片,假设用户保留20次历史记录)
